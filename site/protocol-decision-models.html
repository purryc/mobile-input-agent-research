MOBILE INPUT AGENT / SURVEY
English

协议与决策层 · 研究增量 · 2026-11-17

A2UI 1.0 与 Jev：
先决定控件，再生成界面

对 Mobile Input Agent 的价值，不是让模型接管每次操作，而是把“什么控件此刻有用”与“谁有权执行动作”分开。

证据范围：已核对官方规范、发布文、模型文档与示例仓库；未调用付费模型、未做延迟复测、未接入真实执行器。以下“设计提案”不是已实现功能。

01 · 放回已有架构

本增量接在 Survey 的生成式输入表面与控制协议之后，沿用对象身份、能力核验、请求版本、真实回执及停止／撤销区分。A2UI 可以承载这些信息的界面，却不能替代执行端对这些信息的验证。

用户输入与状态快照
目标、焦点、任务、版本
↓
确定性能力／权限过滤
先删掉不能做的动作
↓
规则 或 决策模型 或 LLM
选择界面，不授予权限
↓
确定性组装 → A2UI → 本地渲染
组件白名单、参数与版本检查
↓
用户操作 → 执行策略检查 → 工具
真实回执、验收、恢复

我方设计提案。连续指针、滚动、旋钮拖动保留在本地低延迟控制回路，不逐帧请求云端决策模型。

02 · 六个层次，不能混为一谈

A2UI
Agent 与渲染器之间的声明式 UI 消息协议；不限定传输必须是 SSE 或 A2A。[P2]
Express
供模型生成的紧凑表示，经过编译成为 A2UI JSON。改变生成格式不必改变客户端。[P4]
Jev / System One
对状态回答类型化问题，输出选择、分数或概率；是决策路径，不是新 UI 协议。[P7]
确定性组装器与 renderer
前者把选项映射到合法组件；后者用宿主组件展示。两者都不应凭空增添执行能力。
MCP / 应用 API
在本架构中作为受权限约束的工具接入层，不等于界面决策模型。
A2A
Agent 协作的另一层；本提案不把它设为使用 A2UI 的前提。

03 · 文章里需要校正的地方

  • 1.0 已发布，但迁移不是全生态瞬间完成。Google 于 11 月 11 日发布 1.0；发布文仍将 Compose 标为 0.9.1、Lynx 标为适配 1.0 中。应锁定具体 renderer 与 catalog 版本。[P1]
  • 旧版命名不能照抄。1.0 的生命周期消息为 createSurface / updateComponents / updateDataModel / deleteSurface；示例中的 beginRendering / surfaceUpdate 不宜作为 1.0 实现指南。新增双向函数调用不等于任意代码执行。[P2]
  • 迁移不是全局替换字符串。@path / @call 等保留键和函数结构发生变化，但 updateDataModel.path 等仍为普通字段。协议内 theme/primaryColor 已移除，宿主主题及自定义 catalog 仍可负责样式。[P3]
  • Jev 官方 SDK 集成仍在路线图。目前可研究自定义组装方案和 jev2ui，不能写成“官方开箱即用”。[P5]
  • 安全性来自多道边界。catalog 白名单不保证业务正确或授权成立；服务端宏能帮助少传敏感字段，但“敏感数据永不进入模型”必须由实际数据流证明，而不是协议自动保证。[P6]

04 · 决策模型值得研究的部分

TypeSafe 的 Choice 返回选项、分布与 confidence；Score 返回评分及相关分布；Noul 返回 0–1 判断值。同批问题独立地基于同一状态评估。复杂多因素问题应拆成原子判断，再由代码组合，不能把一个含糊的大问题换个名字就当成可靠决策。[P7]

Google 展示的混合路径是：Jev 先选布局，代码组装结构，较小 LLM 再填文本。11 个提示的小规模演示报告首棵树 92–298 ms、完整响应 0.8–1.7 s。这是特定示例数据，不是手机端端到端保证；“最高 80 倍”也不能泛化。[P6]

Express 官方测试只有 54 个样本：无 thinking 时输入 token 从 10,980 降到 6,000，输出代码 token 从 807 降到 297，但两者 pass rate 同为 98.1%、quality 同为 97.2%。因此证据首先支持 token 效率，不支持“质量普遍提高”或相同比例提速。[P4]

研究判断：真正可迁移的点是有限选项 + 类型化输出 + 代码约束。模型自报 confidence 不是授权，也不是已在本项目校准的正确率。没有证据仅凭“System One”就能断言其端侧运行、隐私保证或成本优势。

05 · 建议的 Mobile Input Agent 决策契约

以下是独立的应用层草案，不是 A2UI 标准字段，也不是现有 Jev API 的请求格式。

State: task_id, target_id, context_revision,
       focused_role, allowed_actions, execution_status
Decide: surface_kind ∈ {fixed, parameters, draft, review, clarify}
        useful_controls ⊆ allowed_controls
Output: typed_choice + uncertainty + context_revision
Build:  allowlisted component tree + data bindings
Act:    target/version/permission checks + receipt
  • 仅传必要、获准的上下文；不默认采集完整屏幕、邮件、剪贴板或使用历史。
  • 规则优先：已知快捷动作、连续输入和明确确认流程不必调用模型。只对含糊的界面选择使用决策模型；开放式新任务或长文本再交给 LLM。
  • 过滤在前、验证在后：模型只能在当前执行端真实可用的控件中选择；过期 context_revision 的结果丢弃，不能覆盖新焦点。
  • 稳定性比“聪明地跳动”重要：控件位置固定，编辑期间固定布局，只对实质状态变化重算；加入去抖、滞回及明确回退入口。
  • 低置信或冲突时保留固定控件、请求澄清或回到桌面，不发起副作用。阈值须由实际数据校准，本文不虚构通用数值。
  • 执行器再次核对目标、版本、权限、请求期限和幂等键。按钮出现不等于获准；“停止”不等于“撤销已完成操作”。

06 · 从现有四类控件做对照

状态可选界面不能交给模型猜的边界
已选对象，参数 API 可用参数面板／精确输入目标身份、参数范围、读回
文本框有焦点语音草稿／编辑框录音结束不等于发送
空间区域需指明选区画布／范围控制图像版本、坐标变换、提交对象
任务等待介入补充要求／审阅／停止实际能力、请求期限及已生效步骤
目标不明或状态过期澄清／固定导航禁止猜测目标后自动执行

与 Flic Cue 的关系：实体键可以选择入口，但语音仍需明确任务绑定。与 Phase 的关系：形态或模式是状态信号，不是批准信号。这里是架构比较，不主张两款硬件已支持 A2UI 或 Jev。

07 · 最小实验与迁移检查

A/B/C：固定规则基线 vs LLM+Express vs 类型化决策+确定性组装。使用同一 catalog、任务集、客户端与网络条件；从无真实副作用的模拟器开始。

  • 测 p50/p95 可操作界面时间与整项任务时间，同时记录正确控件率、弃权覆盖率、误目标、误操作、纠正次数、布局跳动和恢复成本。
  • 故障集覆盖焦点变化、旧快照、缺失能力、断网、重复动作、低置信、用户正在输入。schema 合法并不代表任务正确。
  • 版本固定并测试能力协商；遵循 1.0 catalog protocolVersion、函数调用限制及 user-activation 约束，不直接运行旧版示例。[P2][P3]
  • jev2ui 是可学习的实验仓库，不等于标准实现认证；其扩展与动态代码路径需单独审计，不复制到生产白名单中。[P8]

建议结论：先验证“有限决策能否比规则更少打扰、比自由生成更稳定”，再决定是否接入 Jev。现阶段更新的是研究与架构，不是模型采购或实现承诺。
