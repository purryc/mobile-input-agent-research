HIDAgent × VIOLOOP

相同的是外接“眼睛＋手”；不同的是，HIDAgent 研究如何跨设备接入，VIOLOOP 把这条路径包装为桌面工作 Agent。

这里的 VIOLOOP 指 Bvio Tech 的硬件产品。硬件能送出按键，不代表它解决了意图理解、权限判断或任务可靠性。

02 / HIDAgent 实际证明了什么？

Jeffrey P. Bigham 的论文把视频观察、输入执行与上层模型解耦。Pico 模拟键鼠，USB 串口连接控制电脑，HDMI 采集卡取屏。六个原型涵盖 UI Agent、界面数据采集、读屏器、跨设备交互、屏幕助手与社交媒体采集。评估主要是描述性观察，不是复杂任务可靠完成的证明。

论文通过校准处理屏幕坐标与相对鼠标位移的差异；当前 GitHub README 则描述视觉闭环指针定位、缓存映射与重新连接检测。应把“论文版本”和“当前实现”分开复现。当前代码与 README

无目标端 Agent ≠ 无设置：论文在 iOS 开启 AssistiveTouch、Full Keyboard Access；Android 允许视频镜像。手机同时承担采集与 HID 通信仍是作者未完成的方向。画面变化检测也不是可靠的人机控制权协议。论文 §3、§5–6

04 / Mobile Input Agent 的研究机会

以下是本调研的设计推演，不是两者已经实现的功能。

  1. 分清三层：手机负责表达、指向与参数修正；决策层选择行动并检查权限；执行层选择 API、辅助功能或 HID。硬件桥是执行通道，不是决策模型。
  2. 批准绑定具体动作：显示目标设备、对象、参数、预期变化；给授权设有效期。画面或对象版本变化时重新确认，不把一次按钮点击视为无限授权。
  3. 接管有明确语义：触碰触控板暂停、松开停止、撤销和恢复分开设计。不能仅用“屏幕变了”推断用户接管。
  4. 测量完整任务：比较不同执行通道的完成率、误点、陈旧上下文、切换设备耗时、恢复成本与 p95 延迟，而不只比模型速度。

最有价值的结合：用 HIDAgent 式桥接扩大实验设备覆盖，借鉴 VIOLOOP 的可见批准入口，但把权限、上下文版本与执行回执作为独立协议。参见 协议与决策层更新。
